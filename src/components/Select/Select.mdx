# Select

Select lets the user pick one option from a list, in a styled popup list. It looks like
[NativeSelect](?path=/docs/components-nativeselect--docs) when closed and takes the same field
props: `label`, `description`, `errorMessage`, `invalid`, `disabled`, `required` and `size`.
Use it when the open list must match your design in every browser. Use NativeSelect when you
want the platform picker on mobile, autofill or native form validation. You pass the choices as
an `options` array, with optional groups.

## Usage

```tsx
import 'greenility-ui/styles.css'; // once, at the root of your app
import { Select, type SelectOption } from 'greenility-ui';

const regions: SelectOption[] = [
  { value: 'north', label: 'North' },
  { value: 'east', label: 'East' },
  { value: 'south', label: 'South' },
  { value: 'west', label: 'West' },
];

<Select name="region" label="Region" placeholder="Choose a region" options={regions} />;
```

### Required

`required` sets `aria-required="true"`, so screen readers announce "required", and shows an
asterisk that is hidden from screen readers. It does **not** block form submission: a
`<button>` cannot take part in native constraint validation. Validate the value yourself, or
use NativeSelect when you want the browser to check it.

### Controlled

Pass `value` and `onValueChange`. `onValueChange` receives **only the value**, as a string.
This differs from NativeSelect's `(value, event)`, because there is no native change event to
pass. Set the value to `''` to clear the selection.

### In a form

With `name`, a hidden input submits the selected value with the form. Nothing is submitted
while nothing is selected, while the value matches no option, or while the Select is disabled.
This matches a NativeSelect showing its disabled placeholder. Outside its form, pass the form's
id in `form`. On form reset, an uncontrolled Select returns to `defaultValue` and calls
`onValueChange` with it.

The box is a `<button role="combobox">` that opens a `role="listbox"` popup. DOM focus stays on
the button the whole time, and the highlighted option is exposed with `aria-activedescendant`.

**Focus.** Focus stays on the combobox while the list is open, including when you click or
scroll the list. Clicking the label focuses the combobox without opening it, as with a native
`<select>`. Selecting an option keeps focus on the combobox.

**Screen reader.**

- Announced as a combobox named by the label, with the selected option's label (or the
  placeholder) as its value, and its expanded state.
- As the highlight moves, the highlighted option is read through `aria-activedescendant`, with
  its selected or disabled state and its group.
- The description and the error are linked with `aria-describedby`, in that order.
- "invalid" comes from `aria-invalid="true"`, and "required" from `aria-required="true"`.
- The chevron and check icons are hidden.

**Form guidance.**

- `required` is announced only. Check for an empty value (`''`) on submit and show an
  `errorMessage`, or use NativeSelect for native validation.
- Validate on submit or when the user leaves the field, not every time the value changes.
- On submit, move focus to the first invalid field.

**What you must provide.**

- A `label`. It is required.
- Options with unique, non-empty `value`s and clear labels.
- An `errorMessage` whenever `invalid` is true.
- Your own validation when the field is `required`.

**Verified.** Automated: unit tests with axe, plus axe on every story in light and dark themes
in Chromium, Firefox and WebKit. Not yet verified with NVDA, JAWS or VoiceOver.

## Do / Don't

**Do**

- Use a Select for one choice from about seven or more options.
- Use a placeholder such as "Choose a region" when there is no sensible default.
- Group long lists with option groups.
- Validate `required` yourself, on submit, and focus the first invalid field.

**Don't**

- Don't use a Select for two to five options. Use a RadioGroup.
- Don't rely on `required` to stop submission. Use NativeSelect if you need native validation.
- Don't use a Select for actions. Use a Menu.
- Don't navigate or submit when the value changes.
- Don't use a Select for multiple choices. Use checkboxes.
