# RadioGroup and Radio

RadioGroup lets the user choose exactly one option from a small set. It renders native radio
inputs that share a `name`, inside a `<fieldset>` named by its `<legend>`. The browser provides
the arrow-key behavior, the single tab stop, form submission and `form.reset()`, with no extra
JavaScript. Each option is a `Radio`, which must be inside a `RadioGroup`.

## Usage

```tsx
import 'greenility-ui/styles.css'; // once, at the root of your app
import { Radio, RadioGroup } from 'greenility-ui';

<RadioGroup label="Reporting period" name="period" defaultValue="monthly">
  <Radio value="monthly" label="Monthly" />
  <Radio value="quarterly" label="Quarterly" />
  <Radio value="yearly" label="Yearly" />
</RadioGroup>;
```

**Pattern.** [WAI-ARIA APG Radio Group](https://www.w3.org/WAI/ARIA/apg/patterns/radio/), met
by native radios in a `<fieldset>`. No roving tabindex is needed.

**Focus and pointer.** The focus ring is on the radio input. Clicking a label selects and
focuses its radio. Each option is at least 24px tall, and the hit area covers the gap to the
label (WCAG 2.5.8).

**Screen reader.**

- The group is a `group` named by the `<legend>`. The group description and error are linked to
  the fieldset with `aria-describedby`, so they are read when focus enters the group, not on
  every arrow press.
- Each radio is announced with its label, its position ("2 of 3"), its checked state, and
  "required" or "invalid" when set.
- The error message is not a live region. On submit, move focus to the first invalid field.

**What you must provide.**

- A group `label` (the legend) that asks the question, and a `label` on every Radio.
- A unique `value` on every Radio.
- An `errorMessage` whenever `invalid` is true.
- A `name` if the form is submitted to a server. Without one, a generated name is used.
- A stable `onValueChange` when the group is controlled.

## Do / Don't

**Do**

- Use a RadioGroup when the user must pick exactly one of two to about seven options.
- Write the legend as a question or a short noun phrase, such as "Reporting period".
- Pre-select a sensible default when one exists.
- Keep option labels short and parallel in grammar.

**Don't**

- Don't use a RadioGroup when several options can be chosen. Use checkboxes.
- Don't use a single Radio on its own. A Radio outside a RadioGroup throws.
- Don't add custom arrow-key handling. The browser already does it.
- Don't create a new `onValueChange` function on every render of a large group.
