# Menu

Menu is a menu button: a trigger that opens a list of actions, such as Edit, Duplicate and
Delete for a row. It is for actions only. For navigation, use links. To choose a value in a
form, use [Select](?path=/docs/components-select--docs). You compose it from `MenuItem`,
`MenuGroup` and `MenuSeparator`.

## Usage

```tsx
import 'greenility-ui/styles.css'; // once, at the root of your app
import { Button, Menu, MenuGroup, MenuItem, MenuSeparator } from 'greenility-ui';

<Menu trigger={<Button variant="secondary">Actions</Button>}>
  <MenuItem startIcon={<PencilIcon />} onSelect={edit}>
    Edit
  </MenuItem>
  <MenuItem onSelect={duplicate}>Duplicate</MenuItem>
  <MenuItem disabled>Archive</MenuItem>
  <MenuSeparator />
  <MenuGroup label="Danger zone">
    <MenuItem onSelect={remove}>Delete site</MenuItem>
  </MenuGroup>
</Menu>;
```

`PencilIcon` stands for any icon element from your own icon set. The `trigger` is cloned with
`aria-haspopup="menu"`, `aria-expanded`, `aria-controls`, an `id` (unless it has one) and event
handlers. Its own handlers run first and its ref is kept.

### Placement and alignment

`placement` is the preferred side (`bottom` by default) and `align` lines the menu up with the
trigger's `start`, `center` or `end` edge. The menu flips and shifts to stay inside the
viewport. `start` and `end` follow the text direction.

### Opening a dialog

`onSelect` runs after the menu has closed and focus is back on the trigger. A Dialog opened
from `onSelect` therefore returns focus to the menu button when it closes. Because `onSelect`
runs in the same user action, it can also copy to the clipboard or open a window.

## Props

### Menu

The ref and any other props go to the `role="menu"` `<div>`. The menu is mounted only while it
is open, so the ref is `null` while closed.

<ArgTypes of={Menu} />

### MenuItem

Renders `<button type="button" role="menuitem">`. The ref and any other props go to it. A
consumer `onClick` runs first and can cancel the selection with `event.preventDefault()`.

<ArgTypes of={MenuItem} />

### MenuGroup

A `<div role="group">` named by its visible `label`.

<ArgTypes of={MenuGroup} />

### MenuSeparator

A `<div role="separator">` between items. It is not focusable and takes no props of its own;
the ref and any `<div>` attributes go to the `<div>`.

**Focus.**

- Only one item is focused at a time; items are not separate tab stops.
- Disabled items stay focusable, so arrow keys reach them and screen reader users can find out
  they exist. They are announced as unavailable and cannot be activated.
- Hovering an item with the mouse moves focus to it, so the keyboard continues from there.
- Activating an item, <kbd>Escape</kbd> and clicking the trigger again return focus to the
  trigger. Tab, a click outside or focus moving elsewhere close the menu without moving focus.

**Screen reader.**

- The trigger is announced as a menu button with its expanded state.
- The menu is named by the trigger. Items are exposed as menu items, which screen readers
  usually read with their position, for example "Duplicate, menu item, 2 of 4".
- Groups are announced with their `label`. Separators are not focusable.
- Icons are decorative and hidden.

**What you must provide.**

- A trigger with a clear name, such as "Actions" or "More actions for Site A".
- Items whose labels are actions (verbs), such as "Duplicate".
- `textValue` for items whose content is not plain text.

**Verified.** Automated: unit tests with axe, plus axe on every story in light and dark themes
in Chromium, Firefox and WebKit. Not yet verified with NVDA, JAWS or VoiceOver.

## Do / Don't

**Do**

- Use a Menu for a set of actions on one thing, such as a row or a report.
- Start item labels with a verb, and end with "…" when the item opens a dialog.
- Group related actions with `MenuGroup`, and put destructive actions last.
- Open a Dialog or AlertDialog from `onSelect` for actions that need more input or a
  confirmation.

**Don't**

- Don't use a Menu for site navigation. Use links in a `<nav>`.
- Don't use a Menu to pick a form value. Use Select or NativeSelect.
- Don't hide a disabled item. Keep it and explain elsewhere why it is unavailable.
- Don't put fields, checkboxes or other controls inside a Menu.
- Don't nest menus.
