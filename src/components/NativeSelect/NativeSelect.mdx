# NativeSelect

NativeSelect lets the user pick one option from a list. It is a styled native `<select>` with a
visible label, optional help text and an error message. Because it is native, it gets the
platform picker on mobile, keyboard typeahead, autofill, form submission and solid screen
reader support without extra code. You pass ordinary `<option>` and `<optgroup>` elements as
children.

## Usage

```tsx
import 'greenility-ui/styles.css'; // once, at the root of your app
import { NativeSelect } from 'greenility-ui';

<NativeSelect name="region" label="Region" placeholder="Choose a region">
  <option value="north">North</option>
  <option value="south">South</option>
</NativeSelect>;
```

## Examples

### With placeholder

`placeholder` adds a first option with `value=""` that is `disabled`. When the NativeSelect is
uncontrolled and has no `defaultValue`, this option is selected at first. The user cannot pick
it again once they choose a real option. When controlled, pass `value=""` to show it.

<Canvas of={NativeSelectStories.WithPlaceholder} />

### Required

Native `required` works with the placeholder. While the empty placeholder option is selected,
the browser treats the field as missing and blocks submission. The asterisk is hidden from
screen readers, which announce "required" once instead. Explain the asterisk once per form.

## Props

`className` and `style` go to the outer wrapper. The ref, `id` and every other prop, such as
`name` and `autoComplete`, go to the native `<select>`. `multiple` is not supported.

## Accessibility

**Pattern.** A native `<select>`, which browsers expose as a combobox (or a listbox) with full
keyboard and screen reader support. No custom ARIA widget is used. A custom listbox would have
to rebuild typeahead, the mobile picker and autofill.

**Keyboard.** Native, so details differ slightly between platforms.

**Focus.** Native. The focus ring is drawn on the whole box. Focus does not move when an error
appears.

**Screen reader.**

- Named by the label, with the selected option read as the value.
- The description and the error are linked with `aria-describedby`, in that order.
- "invalid" comes from `aria-invalid="true"`, and "required" from native `required`.
- The chevron icon is hidden.
- The error message is not a live region. It is read when the select gets focus.

**Form guidance.**

- Validate on submit or when the user leaves the field (blur), not every time the value changes.
- On submit, move focus to the first invalid field, or to an error summary (such as an
  `Alert`) that links to each invalid field.
- Errors are not live regions. A changed `aria-describedby` is not announced again while the
  user stays in the field. If you validate on change, also report the result in your own polite
  region, such as an `Alert` with `live="polite"` that is mounted up front.
- A placeholder is not a label. Put instructions in `description`.
- Explain the "\* required" convention once per form.

**What you must provide.**

- A `label`. It is required.
- `<option>` children with unique `value`s and clear text.
- An `errorMessage` whenever `invalid` is true.
- A `placeholder` when there is no sensible default, especially with `required`.

## Do / Don't

**Do**

- Use a NativeSelect for one choice from a list of about seven or more options.
- Use a placeholder such as "Choose a region" with `required` when there is no good default.
- Group long lists with `<optgroup>`.
- Validate on submit or blur, and focus the first invalid field.

**Don't**

- Don't use a NativeSelect for two to five options that fit on screen. Use a RadioGroup.
- Don't change the page or navigate when the value changes. Users browse options with the arrow
  keys.
- Don't put instructions in the placeholder option.
- Don't use a NativeSelect for multiple choices. Use checkboxes.
