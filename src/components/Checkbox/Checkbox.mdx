# Checkbox

Checkbox lets the user turn a single option on or off, or show a mixed state for a group. It
is a styled native `<input type="checkbox">` with a label, optional help text and an error
message. Because the input is native, form submission, `form.reset()`, label clicks and
autofill all work without extra code.

## Usage

```tsx
import 'greenility-ui/styles.css'; // once, at the root of your app
import { Checkbox } from 'greenility-ui';

<Checkbox name="newsletter" label="Email me the monthly impact report" />;
```

### Indeterminate

`'indeterminate'` shows a dash and is exposed to assistive technology as "mixed". It is a
visual and assistive technology state only. It is not a form value: an indeterminate checkbox
is not checked, so it is not submitted. When the user clicks it, it becomes checked and
`onCheckedChange` receives `true`.

## Props

`className` and `style` go to the root wrapper `<div>`. `ref`, `id` and every other prop, such
as `name`, `value` and `onChange`, go to the native `<input>`.

## Accessibility

**Pattern.** [WAI-ARIA APG Checkbox](https://www.w3.org/WAI/ARIA/apg/patterns/checkbox/), met
by the native input. The mixed state is set through the DOM `indeterminate` property, not
`aria-checked`.

**Keyboard.**

**Focus and pointer.** The focus ring is on the input itself. Clicking the label toggles the
checkbox and focuses it. The box and label are at least 24px tall, and the hit area covers the
gap between them, so there is no dead zone (WCAG 2.5.8).

**Screen reader.**

- The name comes from the label. The description and error are linked with
  `aria-describedby`, in that order.
- "checked", "not checked" and "mixed" come from the native state.
- "required" and "invalid" come from native `required` and `aria-invalid="true"`.
- The error message is not a live region. It is read when the checkbox gets focus. On submit,
  move focus to the first invalid field.

**What you must provide.**

- A `label` that names the option. It is required.
- An `errorMessage` whenever `invalid` is true.
- A `name` (and a `value` if `"on"` is not right) when the checkbox is part of a form.
- The logic for the mixed state. The component shows it but does not compute it.

## Do / Don't

**Do**

- Use a Checkbox for a value that is submitted later, with the rest of a form.
- Write the label as a statement the user agrees to, such as "Email me the monthly report".
- Use the indeterminate state only for a parent of a group of checkboxes.
- Pair `invalid` with an `errorMessage` that says how to fix it.

**Don't**

- Don't use a Checkbox for a setting that applies at once. Use a Switch.
- Don't use a group of checkboxes when only one option may be chosen. Use a RadioGroup.
- Don't expect the indeterminate state to be submitted. Store it in your own state.
- Don't put links or other controls inside the label.
