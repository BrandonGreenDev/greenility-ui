# Decisions

One line per decision, with the reason. Newest at the bottom of each phase.

## Phase 1: Foundation

- Working brand name **Greenility** (`greenility-ui`, token prefix `--gn-`). It is made up and easy to rename before Phase 4.
- ESLint pinned to v9: `eslint-plugin-jsx-a11y` does not support ESLint 10 yet, and jsx-a11y is a requirement.
- Kept `forwardRef` although React 19 accepts `ref` as a prop: it works on both React 18 and 19, so the peer range can stay `>=18.2`.
- ESM-only build with `preserveModules`: modern bundlers tree-shake per file, and CJS adds a dual-package hazard for little gain.
- One compiled `styles.css` that consumers import once, rather than CSS injected by JS: no runtime cost, works with SSR, and CSP friendly.
- Tokens are authored in TypeScript (`tokens.ts`) and generated to CSS: one typed source feeds the CSS, the docs page and the contrast tests, and CI fails on drift.
- Three token layers (palette → semantic → scales): dark mode is just a different semantic mapping, and components never touch raw palette values.
- Hex palette values (not OKLCH): WCAG contrast can be computed exactly in unit tests, and they have universal browser support.
- Contrast is unit-tested for every fg/bg pair in both themes: it catches regressions at the token level, which jsdom-based axe cannot (it has no layout or computed styles).
- axe's `color-contrast` rule is disabled in jsdom tests and checked in the browser by the Storybook a11y addon instead: jsdom cannot compute colors, so the rule produces false results there.
- Theme is selected with `data-theme="light|dark"` on any element (`system` on `<html>` follows the OS): no provider is needed, themes nest, and it works without JS on first paint.
- The library does not reset host page styles: only `[data-theme]` surfaces get a background, color and font, which avoids clobbering consumer apps.
- Reduced motion sets durations to `0.01ms` rather than `0`: `transitionend`/`animationend` still fire, so exit animations cannot hang.
- The Storybook a11y addon runs with `test: 'error'`: violations show as errors in the panel, not warnings.
- Did not add `@storybook/addon-vitest` (browser-mode story tests): it needs Playwright browsers in CI. jsdom tests plus the a11y panel cover the requirement at lower CI cost. Revisit in Phase 4.
- Storybook uses its own `.storybook/vite.config.ts`, so the library build's dts plugin and lib output do not run inside Storybook.
- `react-docgen-typescript` for props tables: it reads JSDoc through `forwardRef` and extended interfaces. A `propFilter` hides inherited DOM attributes.
- Added `scripts/run.ts` to launch Vitest, Vite and Storybook from the real path: on Windows a lower-case drive letter made Vitest load twice and vite-plugin-dts silently skip declaration files.
- `playwright` is a dev dependency only for `scripts/screenshot.ts` (visual checks and README screenshots). It is not used in CI.
- Hand-written `cx` and `composeRefs` instead of `clsx` and similar: about five lines each, so there are zero runtime dependencies.
- Renamed to **Greenility** at Checkpoint 1 (owner's choice). The token prefix is `--gn-` and the package is `greenility-ui`.
- The brand palette is "fern", an original teal-green, to match the name. Light-theme accent uses fern-700 (6:1 on white). It is teal enough to stay distinct from the yellower `success` green, and status always comes with an icon or text anyway.

## Phase 2: Core components

Full spec: `docs/specs/phase-2.md`.

- **Errors use `aria-describedby`, not `aria-errormessage`.** `aria-errormessage` is still not announced by VoiceOver, and NVDA support is partial. Using both double-announces in JAWS.
- **`aria-describedby` order is description then error,** matching visual order.
- **Field errors are not live regions.** Announcing on every keystroke validation is noisy. Errors are read on focus, and the docs tell consumers to focus the first invalid field on submit.
- **Required fields use native `required` plus an aria-hidden asterisk.** Required is announced once, with no "star", and native validation stays available (consumers can use `noValidate`).
- **Native form controls receive `value`/`checked` directly instead of going through `useControllableState`.** The DOM already owns the state. Mirroring it in React breaks `form.reset()` and autofill and risks controlled/uncontrolled warnings. `useControllableState` stays for non-native state (`open` in Phase 3).
- **On field components, `className`/`style` go to the root wrapper and `ref`/`id`/rest go to the native control.** Layout styling and DOM access each land where they are useful.
- **Button variants are primary, secondary, ghost and danger, with no separate `tone`.** Only one destructive style is needed, and a variant × tone matrix would add untested contrast pairs.
- **Button defaults to `type="button"`.** This prevents accidental form submits.
- **A loading Button uses `aria-disabled` and swallows clicks, not `disabled`.** Native `disabled` drops focus to `<body>` mid-interaction. The label stays in the DOM at opacity 0 to keep the accessible name and width.
- **A disabled (not loading) Button uses native `disabled`.** It matches platform behaviour and removes the button from the tab order.
- **IconButton `label` is a required `string` mapped to `aria-label`, and `aria-labelledby` is omitted from its props.** A name is guaranteed at compile time.
- **IconButton composes Button through a `data-icon-only` attribute.** There is one source of variant and loading logic and no duplicated CSS.
- **Checkbox uses `checked: boolean | 'indeterminate'`.** A single source of truth makes "checked and indeterminate at once" unrepresentable. `onCheckedChange` always returns a boolean, because the user can only produce boolean states.
- **Checkbox indeterminate is set through the DOM `indeterminate` property, not `aria-checked`.** The browser exposes "mixed" natively and clears it on user input.
- **Checkbox, Radio and Switch style the real input with `appearance: none`, with glyphs as aria-hidden siblings.** The focusable, clickable element is the real input, which keeps forms, labels and forced-colors behaviour.
- **RadioGroup uses native radios in a fieldset with a legend, not an ARIA radiogroup with roving tabindex.** Browsers implement the APG keyboard model, single tab stop and form submission natively, with no JS.
- **RadioGroup puts `aria-invalid` and `required` on each radio and describedby on the fieldset.** `aria-invalid` and `aria-required` are not supported on `role=group`. Group help is read on entry without repeating on every arrow press.
- **Switch is `<input type="checkbox" role="switch">`, not `<button role="switch">`.** It gets native name/value form submission, reset, label click and Space toggling for free. AT without switch support still hears a correct checkbox.
- **Switch has no invalid or error props.** A switch applies its change immediately and is not validated.
- **Select uses a native `<select>`.** It provides robust keyboard support and typeahead, the mobile picker, autofill, form participation and AT support, all of which a custom listbox would have to reimplement. A custom listbox can be reconsidered when `appearance: base-select` is widely supported.
- **The Select placeholder is a disabled `value=""` option, not `hidden`.** iOS ignores `hidden` on options.
- **TextArea `autoResize` uses CSS `field-sizing: content`.** No JS measuring is needed, and unsupported browsers fall back to a fixed, user-resizable height.
- **TextField adornments are not auto-linked to the input description.** Most adornments are decorative icons. Units should also appear in the label or description.
- **Alert uses a `live` prop (`off` → no role, `polite` → `status`, `assertive` → `alert`) with default `off`.** Most alerts are static page content, and `role="alert"` interrupts the user, so it should be opt-in.
- **Alert neutral tone is included and accent is excluded.** Neutral covers plain notices. Accent is a brand colour, not a meaning for messages.
- **Alert announces its tone with a visually hidden prefix (`toneLabel`).** Tone otherwise lives only in colour and an aria-hidden icon (WCAG 1.4.1).
- **Alert dismissal is consumer-controlled (`onDismiss`).** The Alert holds no hidden state, and the consumer decides removal and the focus target.
- **Spinner is `role="status"` with visually hidden text, and `decorative` hides it inside Button.** Live regions announce text content, not `aria-label`. The Button already conveys its own state.
- **Under reduced motion, the Spinner swaps rotation for a slow opacity pulse.** It still signals busy without spatial motion. Its loop tokens are `loop-*` so they are not collapsed to 0.01ms, which would make them flash.
- **Status icons use four distinct shapes (circle-i, circle-check, triangle, octagon).** Tone stays distinguishable without colour.
- **Icons are internal in Phase 2.** This keeps the public API small; they can be exported later without breaking changes.
- **Disabled states use semantic colour roles, with no opacity token.** Opacity over arbitrary backgrounds gives unpredictable colours.
- **Batches do not edit `src/index.ts`, `DECISIONS.md` or tokens.** These are the only files all batches would share, so the integrator owns them to avoid merge conflicts.
- Added a shared `Orientation` type to `src/utils/types.ts` (used by RadioGroup).
- `FieldLabel as="legend"` drops `htmlFor`, because `for` is not valid on `<legend>`; the legend greys out from a parent `fieldset:disabled` or `[data-disabled]`.
- `useField` sets `aria-describedby` ids only when that content renders, so it never points at a missing element.
- An invalid field box uses a `Mark` border in forced-colors mode rather than a thicker border: there is no layout shift and no raw px value.
- Icons accept `className` and forward a ref to the `<svg>`, consistent with every other component.
- Button positions its loading Spinner with a higher-specificity selector (`.root > .spinner`): with `preserveModules` the consumer's bundler decides CSS order, so cross-module overrides must win on specificity, not order.
- IconButton passes its icon through Button's `startIcon` slot with `children={null}`, so it reuses Button's aria-hidden icon wrapper, sizing and loading styles.
- Button `loadingLabel` (default "Loading") is an aria-hidden VisuallyHidden span referenced by `aria-describedby` while loading: the name stays the label, and screen readers hear that it is busy.
- IconButton warns on an empty or whitespace `label` (with no env check, because library code avoids `process.env`).
- Alert puts its live role on the message wrapper (prefix, title, body), not the root, so the icon and dismiss button are not re-announced with each update.
- Alert uses an `auto 1fr` grid plus an implicit auto column, so there is no empty gap when the alert has no dismiss button.
- The neutral Alert's dismiss hover border uses `border-strong` (border-default on bg-muted is about 1.2:1).
- Live regions (Alert `live`, Spinner) are documented as "mount first, then change content", because a role added on mount is not reliably announced.
- A `Radio` outside a `RadioGroup` throws in every environment: without the group it has no shared name or value, so it is always a programming error.
- Checkbox, Radio and Switch share `Field/indicator.module.css` for layout, states and forced colors. Indeterminate rules stay in Checkbox, because radios match `:indeterminate` when nothing in the group is selected.
- Indicator glyphs are centered by stacking them with the input in one grid cell, not with `translate(-50%, -50%)`: a physical transform is off-center in RTL.
- Indicator controls and labels are at least `--gn-size-target-min` (24px) tall, and a transparent `::before` widens the hit area across the gap to the label (WCAG 2.5.8, no dead zone).
- The Switch thumb moves with a logical `inset-inline-start`, so it slides the right way in RTL with no direction-specific rule.
- A disabled checked Switch fills its track with `fg-disabled`, so disabled on and off stay distinguishable, consistent with Checkbox and Radio.
- In forced colors, invalid controls show a thicker border in the system color, not `Mark`: Mark is a fixed yellow that is about 1.1:1 on light high-contrast themes.
- A controlled Checkbox restores `indeterminate` before consumer callbacks run, so handlers see the DOM as React will render it.
- Badges are not live regions; consumers announce changing statuses in a separate polite region.
- `danger-border` and `accent-solid-hover` contrast is tested against every surface, because indicators sit on cards and dialogs too.
- In forced colors, an invalid text box shows a thicker border; the first and last child are pulled outwards by the extra width, so text and adornments do not move.
- The shared control frame uses `box-sizing: border-box`, so the box height equals its `--gn-size-control-*` token exactly.
- The text-control focus ring shows on `.box:has(> .input:focus)`, not `:focus-within`, so a focused adornment button shows its own ring instead of lighting up the whole field.
- Shared `:has()` state rules use the child combinator (`> .input`), so a disabled placeholder `<option>` or adornment button cannot make the whole field look disabled.
- Read-only fields use a `fg-muted` placeholder, because `fg-subtle` on `bg-subtle` is 4.33:1.
- `useField` warns when `invalid` is set without an `errorMessage`, since the error would otherwise be shown by color alone (WCAG 1.4.1, 3.3.1).
- `onChange` then `onValueChange` composition lives in `utils/composeChange.ts`, and the renderable check lives in `utils/isRenderable.ts`, shared by all field components.
- Select's end padding scales with size, so the large chevron never overlaps the text; the placeholder is grey only when enabled.
- TextField adornments are not part of the input's name or description: units belong in the label or description.
- Added `npm run test:a11y` (also in CI): axe runs in real Chromium against every built story in light and dark. It covers what jsdom cannot, chiefly color contrast as rendered. It replaces the need for `@storybook/addon-vitest` at a fraction of the setup.
- Docs pages use `tags: ['!autodocs']` in the stories file, because autodocs is enabled globally in `preview.tsx`.

## Phase 3: Advanced components

Full spec: `docs/specs/phase-3.md`.

- **No Portal: overlays render in place and reach the top layer through `<dialog>.showModal()` and `popover="manual"`.** Theme inheritance from `[data-theme]` is kept, there are no z-index wars, and content inside a modal stays non-inert.
- **Positioning is a small pure JS `computePosition` (flip, shift, RTL), not CSS anchor positioning.** Anchor positioning is not yet Baseline widely available, so a JS fallback would be needed anyway. One path is testable; revisit later.
- **The floating offset and edge padding come from a CSS margin token (`--gn-space-1`), which the positioner measures.** No px constants in JS.
- **`popover="manual"`, not `auto`.** Auto light-dismiss fights the trigger toggle and bypasses our focus return. One `useDismiss` model serves Tooltip, Menu and Select.
- **Escape uses a capture listener with a layer stack for floating layers; Dialog ignores `defaultPrevented` Escape and guards `cancel`.** The innermost layer always closes first.
- **Non-native state callbacks receive only the value (`onOpenChange(open)`, `onValueChange(value)`).** There is no native event to pass, and it matches `useControllableState`.
- **Consumer handlers on cloned triggers run first; ours are skipped after `preventDefault()`.** Consumers can always veto library behaviour.
- **Dialog uses native `<dialog>` + `showModal()` instead of `role="dialog"` with a JS trap.** Inert background, top layer, backdrop and Escape come from the platform. Tab may leave to the browser chrome, which is accepted platform behaviour.
- **Dialog has a prop-based API (`title`, `description`, `footer`, `trigger`) plus `DialogClose`, not a six-part compound.** The name and description are wired correctly by construction, with the smallest API.
- **AlertDialog is a separate component with a required `description`, initial focus on Cancel, no close button and no backdrop close.** Destructive confirmations cannot be dismissed by accident, per APG.
- **Dialog scroll lock is pure CSS (`html:has(dialog[open])`, with `overflow: hidden` and `scrollbar-gutter: stable`).** No JS ref counting, no layout shift, and nesting works.
- **Dialog has an enter animation only; closing is instant.** Discrete exit transitions (`overlay`, `allow-discrete`) are not cross-browser.
- **Dialog initial focus prefers body content over the header close button.** Users start in the content, and the close button's tooltip does not flash on open.
- **Dialog content unmounts while closed; the `<dialog>` element stays mounted and never renders `open` from React.** State resets, there are no dangling ids, and it is SSR-safe.
- **Toasts move into the topmost open modal through `OverlayHostContext`.** Otherwise `showModal()` makes them inert, so they could not be clicked and were not announced.
- **Toast announcements use a separate always-mounted polite region with message text only.** Buttons are not read out, and the Phase 2 "mount first" rule holds.
- **All toasts are polite, including danger.** `role=alert` stays reserved for the Alert component's opt-in `assertive`.
- **Toasts with an action and danger toasts do not auto-dismiss by default; timers pause on hover, on focus and when the tab is hidden, and the provider `duration` can be a user setting.** This meets WCAG 2.2.1.
- **The toast hotkey is F8, not F6.** Browsers use F6 to cycle panes.
- **At most 3 toasts are visible and extras queue rather than drop.** Persistent action toasts are never lost.
- **Toast ids combine the provider's `useId()` with a provider-local ref sequence.** They are scoped and SSR-safe, with no module-level counter.
- **Tooltip is always mounted (hidden when closed) and opens on hover after a delay or on `:focus-visible` immediately; touch is ignored.** `aria-describedby` always resolves, and mouse clicks do not flash tooltips.
- **IconButton shows its `label` as a decorative (aria-hidden) tooltip by default; the name stays on `aria-label`.** No double announcement, and the name never depends on the tooltip node.
- **Tooltip `decorative` reuses Spinner's vocabulary.** "Hidden from AT; the parent supplies semantics" means the same thing everywhere.
- **Menu scope is `menuitem`, group and separator; checkbox and radio items are deferred.** This avoids a second state API in Phase 3 and can be added without breaking changes.
- **Disabled menu items stay focusable (`aria-disabled`), while disabled tabs and Select options are skipped.** The first follows APG's menu guidance; the second matches native tabs and `<select>`.
- **MenuItem `onSelect` runs after the menu closes and focus returns to the trigger.** A Dialog opened from a menu then returns focus to the menu button.
- **Phase 2 `Select` is renamed `NativeSelect` with an identical API; the new `Select` is a custom select-only combobox.** The owner asked for a custom Select. The native one stays for mobile pickers and native validation.
- **The custom Select takes an `options` array (with groups), not `<SelectOption>` children.** Typeahead, indexing and activedescendant ids work without registration effects, and it is SSR-safe.
- **The custom Select combobox is a `<button role="combobox">`.** It gets native disabled, focus and `type=button`, and ARIA in HTML allows the role.
- **The custom Select maps `required` to `aria-required` and submits through a hidden input; it resets on form `reset`.** Native `required` is invalid on a button. NativeSelect is documented for native validation.
- **A custom Select label click focuses the combobox without opening it.** This matches native `<select>`.
- **`''` is the "nothing selected" value for Select and single Accordion.** It matches NativeSelect's placeholder value and keeps `useControllableState` controlled detection simple.
- **Tabs and Accordion query their items from the DOM on keydown instead of registering them.** Order always matches the DOM, with no effects or index bookkeeping.
- **All tab panels stay mounted (inactive ones `hidden`).** Panel state is kept, and `aria-controls` always resolves.
- **The selected-tab indicator is a `::after` background painted `Highlight` in forced colors, not a border.** Transparent borders become visible in forced colors and would erase the difference.
- **Accordion is the APG button-in-heading pattern, not `<details>`.** Heading semantics are lost inside `<summary>`, non-collapsible mode cannot be enforced, and height animation there is Chromium-only.
- **Accordion animates with `grid-template-rows` 0fr↔1fr and `visibility`.** No JS measuring, cross-browser, closed content leaves the a11y tree, and reduced motion collapses it through tokens. Find-in-page reveal is traded away.
- **RTL is read from the nearest `[dir]` ancestor.** It is deterministic in jsdom; CSS-only `direction` is documented as unsupported.
- **DataTable is a native `<table>` with sort buttons in headers, not `role=grid`.** Cells are not interactive, so grid navigation would only add keystrokes.
- **DataTable requires a `caption` (with `captionHidden`).** Every table has a name, which also labels the scroll region.
- **The DataTable scroll container gets `role=region`, a label and `tabIndex=0` only while it overflows.** It meets WCAG 1.4.10 and 2.1.1 without a landmark and tab stop per table.
- **DataTable announces sort, page and loading changes through one always-mounted polite region; the visible range text is not live.** One announcement per action, no duplicates.
- **DataTable Prev/Next use `aria-disabled` at the bounds (Stage 0 Button style).** Native `disabled` would drop focus to `<body>` on the last page.
- **A sort or page-size change resets DataTable to page 1, and an out-of-range page is clamped for display without a callback.** The user always sees the start of the new ordering.
- **DataTable `manual` mode (with `totalRows`) is included.** Controlled sort and page and the loading state are only useful with server data.
- **DataTable row selection is deferred.** The scope stays reasonable, and `getRowId` already exists for it.
- **DataTable column header is `header: string` and the column type is exported as `DataTableColumn<Row>`.** The sort announcement needs text, and a bare `Column` export is too generic for the package index.
- **DataTable uses a generic `forwardRef` cast pattern.** `forwardRef` erases generics, and the cast keeps `Row` inference.
- **DataTable `className`/`style` go to the root wrapper, and ref/rest go to the `<table>`.** This mirrors the field rule: layout on the wrapper, DOM access on the main element.
- **Floating surfaces show the active item with an inset focus ring, not only a background change.** `bg-hover` on `bg-raised` is about 1.1:1, which fails 1.4.11.
- **jsdom shims for `showModal`, `popover` and `scrollIntoView` are feature-detected in `setup.ts`.** Tests run today and automatically use real implementations when jsdom adds them.
- The optional "n/a guard" contrast pair (`accent-subtle-fg` on `bg-raised`) was dropped: in forced colors the system palette replaces both colours, so it tested nothing real. All other Phase 3 pairs pass in both themes.
- `toIdPart` also escapes `_` (the spec kept it): otherwise `'a b'` and the literal `'a_w_b'` would share an id, so the mapping would not be injective.
- `mergeProps` lets our `aria-expanded`/`aria-controls`/`aria-haspopup` win whenever we pass the key, even as `undefined`, so `aria-controls` disappears while closed. A consumer `id` wins, so components read the final trigger id back (`trigger.props.id ?? ourId`).
- `getElementRef` checks the React major version: React 19 reads `props.ref`, React 18 reads `element.ref`. Reading `element.ref` in React 19 logs a warning.
- `getNextIndex` `{ by: n }` moves across n enabled items (the Select "move 10 enabled options" rule), not n raw indexes. Without `loop`, `next`/`prev` stay on `from` at the ends.
- `useTypeahead` takes a structural event (`key`, modifier flags, `preventDefault`), so React and DOM events both work. It calls `preventDefault()` on every key it consumes, so a Space inside a search never activates the item.
- `useFloating` widens the anchor by the floating margin on the cross axis, so `align` lines up the visible border box (not the margin box) with the anchor edge. It also subtracts the block margins from `--gn-floating-available-block-size`.
- `useFloating` measures in a layout effect plus one rAF follow-up. Components must show the popover in a layout effect declared before the hook. A `dir` change while open is picked up on the next resize or scroll.
- `useIsOverflowing` also watches direct children (ResizeObserver) and child-list changes (MutationObserver), because a fixed-size scroll box does not resize when only its content grows.
- `useFocusReturn` does not capture `<body>`, so restoring after a pointer-only open is a no-op rather than a blur.
- `.floating` adds `box-sizing: border-box` and a `--gn-z-dropdown` default (Tooltip overrides it with `--gn-z-tooltip`), so `matchAnchorWidth` equals the anchor's border box. Items also get the ring on `:focus-visible`, as well as `[data-active]`.
- The jsdom setup also shims `HTMLDialogElement.prototype.show` and the `open` property alongside `showModal`/`close`. jsdom 29.1.1 has none of the dialog, popover or `scrollIntoView` APIs. `ResizeObserver` is deliberately not shimmed, so hooks exercise their no-RO path and tests stub it explicitly.
- `src/components/Floating/index.ts` is an empty module (`export {}`). Components import `floating.module.css` directly.
- Phase 3 public types (`Placement`, `Align`, `ActivationMode`, `SortDirection`, `SortState`) are exported from the package index. Stage 0 utils, hooks and icons stay internal, as in Phase 2.
- (Replaces the "query their items from the DOM ... no effects or index bookkeeping" line above.) Tabs and Accordion use the DOM as their item registry. Accordion queries its own `[data-accordion-trigger]` buttons on keydown. Tabs keeps the enabled tab values in DOM order, re-read by a stable `sync()` from layout effects with an equality guard; the default selection and roving tab stop are derived during render, with no index bookkeeping.
- Uncontrolled Tabs with no `defaultValue` select the first enabled tab without calling `onValueChange`; re-selecting the current tab never calls it.
- With manual activation, the tab stop follows the focused tab while focus is in the tablist and resets to the selected tab on leaving, so Tab leaves from where the user is (APG).
- An overflowing tablist fades its edges with `mask-image` and reveals the selected tab by adjusting the list's `scrollLeft`, not `scrollIntoView`, so the page never scrolls.
- A focused tab that is disabled or removed hands focus to the new tab stop; an Accordion panel closed from code while holding focus returns focus to its trigger.
- Closed Accordion panels are `inert` (set on the DOM node, because React 18 and 19 handle the prop differently), and open panels use `visibility: inherit`, so nested open panels stay hidden inside a closed parent.
- Tabs and Accordion state styles use child combinators keyed on their own list or trigger, so nested instances stay independent; Tabs must be direct children of TabList.
- `Tab` and `TabPanel` props omit the ids and ARIA that Tabs manages, so misuse fails to compile.
- A locked-open Accordion trigger (non-collapsible) keeps `aria-disabled` per APG, hides its chevron, and keeps its title at full contrast.
- The tab focus ring is inset by the ring width plus the indicator height, so the selected bar stays visible under focus.
- DataTable announcements are held as pending and committed after 150ms. While loading, sort and page messages are held and announced once, combined with the range, when loading ends: one message per action, never overwritten by "Loading".
- DataTable announces "Loading" only when no user-triggered message is waiting (on mount or a parent-driven refresh).
- The DataTable status text is keyed by a nonce inside an always-mounted region, so identical consecutive messages are still announced; clearing a sort announces `messages.unsorted` ("Sort cleared").
- The DataTable scroll region keeps role, label and tabIndex while focused even if overflow stops, so focus never sits on an unnamed element.
- The DataTable pagination group is named "Pagination" plus the caption and described by the range text, so several tables on one page stay distinct; buttons default to "Previous page"/"Next page".
- DataTable infers `Row` from `rows` only (`NoInfer` on `columns`/`getRowId`), so mismatches are reported on the column definitions; an empty literal `rows={[]}` needs a typed array.
- DataTable sanitises non-finite `page`/`pageSize`/`totalRows`; NaN would otherwise loop the render-phase change detection.
- The DataTable header uses `bg-muted`, not `bg-subtle`, because in the light theme `bg-subtle` equals the canvas.
- DataTable warnings fire once per instance; the range text is empty during a first load with no rows.
